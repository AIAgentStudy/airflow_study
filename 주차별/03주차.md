## 상세 수행방법

## 0) 이번 주 목표(한 줄)
- @task 함수 반환값 전달, XCom 확인, Jinja 템플릿

## 1) 시작 전에 준비할 것(10분)
- [ ] Docker Desktop 실행 확인
- [ ] Airflow 컨테이너 실행 확인: docker compose ps
- [ ] DAG 폴더 경로 확인(예: C:\airflow-local\dags 또는 본인 환경의 dags 폴더)
- [ ] 진행 기록 파일 준비: 진행현황/진행추적표.md

## 2) 공식 문서 읽기(40~60분)
- 1순위 문서
  - https://airflow.apache.org/docs/apache-airflow/stable/tutorial/taskflow.html
  - https://airflow.apache.org/docs/apache-airflow/stable/core-concepts/xcoms.html
- 읽는 방법(영문 문서가 어려울 때)
  - [ ] 목차만 먼저 훑고 "새 용어 5개"만 적기
  - [ ] 코드 블록을 먼저 읽고, 설명 문단은 핵심 문장만 표시
  - [ ] 이해 안 되는 단어는 한국어로 한 줄 정의 후 넘어가기

## 3) 실습(핵심 구현 과제)
- 실습 DAG 이름(권장): study_taskflow_etl
- 템플릿
  - templates/dags/etl_taskflow.py
- 이번 주 핵심 실습
  - extract->transform->load DAG 작성 및 값 전달 확인
- 구현 공통 규칙
  - [ ] retries와 retry_delay를 반드시 명시
  - [ ] 태스크 단위 execution_timeout(또는 유사 timeout) 명시
  - [ ] catchup=False로 시작(개념 이해 후 필요 시 변경)

## 4) 실행과 확인(필수)
1. DAG 파일을 dags 폴더에 저장
2. UI에서 DAG가 보이는지 확인
3. 수동 실행(Trigger DAG)
4. Grid/Graph에서 태스크 상태 확인
5. 각 태스크 로그 열어 시작/종료/에러 라인 위치 확인

## 5) 검증 과제(의도적 실패 1회)
- 실패 시나리오
  - transform에서 특정 입력값일 때 예외를 발생
- 복구 순서
  1. 실패 원인 1줄 요약(어떤 설정/코드가 문제였는지)
  2. 코드 또는 설정 수정
  3. 실패 Task만 재실행(전체 재실행 금지)
  4. 성공 로그로 복구 확인

## 6) 증빙 자료 정리(제출용)
- [ ] DAG 그래프 화면 캡처 1장
- [ ] 실패 로그 캡처 1장
- [ ] 복구 성공 로그 캡처 1장
- [ ] 회고 5~10줄
  - 왜 실패했는지
  - 무엇을 바꿨는지
  - 다음 주에 반복 방지할 점

## 7) 완료 기준(셀프 체크)
- [ ] 핵심 개념을 노트 없이 2~3분 설명 가능
- [ ] 같은 DAG를 새 환경에서 다시 실행 가능
- [ ] XCom 탭에서 payload가 전달되는지 확인

## 8) 막히기 쉬운 포인트(초보용)
- DAG가 UI에 안 보이면
  - [ ] 파일명/파이썬 에러 확인
  - [ ] scheduler/webserver 로그 확인
- 실행이 계속 대기면
  - [ ] Pool/Concurrency/의존성 조건 확인
- 실패 원인이 안 보이면
  - [ ] 태스크 로그의 첫 에러 라인부터 읽고, traceback 마지막 줄 키워드 기록
